# 产品范围摘要

物序用于登记和审计个人物品，核心信息包括名称、两级类目、数量、存放位置、图片、可选到期日期、物品状态和消耗品属性。当前用户端不要求填写单位，新登记物品由系统使用固定默认单位保持数据兼容。

物品状态包括：

- `IN_USE`：使用中
- `UNUSED`：未使用
- `DAMAGED`：已损坏
- `CONSUMED`：已消耗

用户端负责个人物品登记、查找、状态维护和个人存放位置；管理后台负责全局类目、全局存放位置以及授权范围内的查询和统计。

## 已实现范围

- 大类目和小类目由管理员统一维护，普通用户登记物品时只能从后台配置的类目中选择；物品保留类目名称快照。
- 图片按用户选择顺序关联到物品；每个文件独立校验，失败不会影响其他文件。
- 图片文件保存在 S3 兼容对象存储，SHA-256 等元数据与业务文件分开保存。
- 用户统计包含记录数、数量、状态、类目、30 天内到期和已过期。
- 管理后台只读展示跨用户统计与物品列表，不修改用户物品；管理员可维护全局两级类目和存放位置。
- 管理后台的数据中心、类目管理和位置管理分别使用独立页面，避免管理表单与统计查询混在同一页面。
- 存放位置分为管理员创建的全局位置和用户创建的个人位置，均包含名称、说明和必填照片。个人位置仅创建者与管理员可见。
- 用户登记物品时只能选择全局位置或本人的个人位置，不能在物品表单中输入任意位置文本。
- 用户端提供独立的新增位置与查找位置页面，可以按名称或说明搜索、查看位置内的个人物品；个人空位置允许本人删除，非空位置禁止删除。
- 管理后台统一查看全部位置和全局物品数量，并通过范围标签区分全局位置与个人位置。
- 用户端首页作为功能入口，物品与位置的查找、新增均为独立页面，并适配移动端操作和底部导航。
- 到期日期为选填项。用户先勾选“有到期日期”，表单才显示并要求填写日期；取消勾选时清除尚未提交的日期。
- 物品可以标记为消耗品。选择消耗品时必须登记预计使用天数；物品进入“使用中”时系统才记录本轮开始时间，并展示已使用天数、预计天数、时间进度和按初始数量计算的预计日均消耗。
- 消耗品达到预计使用天数后在用户首页、物品列表和管理后台显示检查提醒，并可按“待检查消耗品”筛选；提醒不会自动修改物品状态。

## 消耗品跟踪规则

- 历史物品和未明确标记的物品默认是非消耗品，保持向后兼容。
- 消耗品是独立的物品类型，不受当前状态限制；“未使用”等非使用中状态也可以标记为消耗品，并必须提前填写预计使用天数，但只在状态为“使用中”时计算进度。
- 预计使用天数为 1 到 36500 之间的整数，单位固定为天。
- 消耗品从进入“使用中”的时间开始计算本轮进度；离开“使用中”后停止并清除本轮开始时间，但保留预计使用天数，再次进入时沿用该周期并开始新一轮。
- 用户端首页展示最近的使用中物品，并提供进入完整使用中列表的入口。
- 使用进度采用 `已使用天数 / 预计使用天数` 展示，进度上限为 100%。
- 预计日均消耗为 `登记数量 / 预计使用天数`，属于计划值，不代表系统已经扣减库存。
- 达到预计天数时仅生成站内检查提示。用户检查实物后，可以调整预计周期或手动将状态改为“已消耗”。
- 当前不包含操作系统通知、短信、邮件、推送、自动扣减数量或自动变更状态。

## 数据部署要求

- 用户与身份数据继续使用 MySQL；类目、位置、物品、状态历史和媒体元数据继续使用 MongoDB。
- MongoDB 支持两种互斥部署模式：默认使用 Compose 内的本地 MongoDB，也可以连接 MongoDB Atlas 在线数据库。当前目标 Atlas 项目名称为 `WUXU_MONGO`，实际项目和集群由部署时的连接串确定，不把项目标识或凭据硬编码到业务代码。
- Atlas 模式不启动本地 MongoDB 容器；MySQL 与图片对象存储的部署方式不变。
- Atlas 连接串只能通过未提交 Git 的环境文件或部署 Secret 注入。Atlas 控制台、Admin API 或 AI 密钥不能替代数据库连接串。
- 切换到 Atlas 前必须准备数据库用户、网络 IP Access List 和 TLS/SRV 可用的驱动连接串，并通过 API 就绪检查验证连接。
- 本地 MongoDB 使用宿主机目录备份；Atlas 模式使用 Atlas 备份能力或逻辑导出，不能把空的本地 MongoDB 目录当作云端备份。
